## 1. 一句话

**stockdb-ai = AI 原生市场数据基座。** 产品形态 = MCP + HTTP 数据接口
（AI 友好、可信、只读为主、时点契约）；上游 free-stockdb 引擎是数据层
provider 之一，不是架构依赖。

## 2. 各部件职责

| 部件 | 职责 | 状态 |

| MCP 服务器（/mcp，57 工具） | **核心产品：AI 取数入口**（行情/指标/选股/竞价/打板/仓库 SQL），统一契约信封 + 时点语义 | 持续打磨，按需加工具 |

| 采集链（打板/竞价） | 数据基座唯一自取能力：9:26 快照 + 收盘对账收口 → 打板序列/指标 | 运行中 |

## 3. 使用姿态（价值出口，配比自由、可并存）

- **A 问答台（默认姿态）**：想到就问——AI 一句话 → 工具调用 → 契约答案
  （范例：08-27 全市场 MACD 金叉筛 23s 命中 307 只）。过程可迭代可追溯 =
  「复现协议」三铁律：①先存 request 再调用；②改参数 = 新 run，不覆盖旧
  输出；③结论必须挂 run id + known_at。候选题进问题池
  （docs/research/question-pool.md）。
- **B 情报订阅（可选件，未立项）**：每日 AI 自动读库出《昨日市场日报》，
  用户只负责读。
- **C 正式课题（按需）**：定义书流程（docs/research/TEMPLATE.md 十节骨架）
  仅当某问题值得深挖到可能改变操作时启用；一次一个，跑完再捞。
- **D 纯基座**：不索取任何研究产出也是合法归宿——好工具可以是安静的。

## 4. 该做什么 / 不该做什么

该做（按优先级）：
1. **维护**：数据新鲜度/稳定性问题即修（命根子）；
2. **契约完善**：发现数据不可信/字段语义不清就修；
3. **按需扩工具**：由真实问题倒逼（56 个已够多，"攒批加工具"时代结束）；
4. **数据层扩展**：加数据源 = 加一个 provider（如港股延伸线，见 §6）。

不该做（戒律，⚡ = 08-27 实战新增）：
- ❌ 面板不加功能；不做执行/模拟盘；不在 NAS 上做因子计算与回测；
- ❌ ⚡不主动追上游新版本——构建坏了才修，修复必 pin SHA256；
- ❌ ⚡不为镜像源协议写适配层——上游换域只改 /data/sync_url.txt 配置；
- ❌ ⚡功能分支合并或归档期限 = 一周（防 verbatim-mirror 式悬挂）；
- ❌ ⚡非维护类 PR 描述必须引用它解卡的具体问题，否则移入问题池/延后项；
- ❌ 不引入付费实时行情源；不换技术栈（维持 v1 结论）。

## 5. 人力配比与熔断

A 问答/研究 70% · B 倒逼式最小基建 20% · C 维护 10%。
周五自查：连续两周 B+C > 50% 且无任何使用产出 → 停手，回读本文件。

      AI 经 get_mydb_data 读取

HK0100，规范形 hk00100；实测上市日 2026-01-09，已入库 156 根）。
⚡代码标识设计（用户 08-28 拍板）：**对外一切标识统一 `hk` + 5位补零前缀形**
