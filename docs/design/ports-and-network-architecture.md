# StockDB 端口、前后端职责与 MCP 接入架构权威说明（2026-11-02）

> **目的**：消除历史文档中关于端口（7899 / 8080 / 8081）与前后端属性的歧义，明确消费方唯一稳定的后端访问端点，杜绝“8081 是前端页面代理”或“7899 是真实后端”的误解。
> **基线环境**：`stockdb-native 0.16.0`，Git 提交 `5bd9cb9eae5919478041016cc7c74b793b4865d4`，镜像 `stockdb-ai:0.16.0`。

---

## 1. 实际部署端口与进程拓扑

| 宿主机端口 (NAS) | 容器内部端口 | 监听进程 | 协议 / 格式 | 职责定位 | 访问对象 / 权限 |
|---|---|---|---|---|---|
| **`8081`** | **`8080`** | `python /opt/webui/app.py` (PID 45) | HTTP/1.1<br>JSON-RPC 2.0 / REST / HTML | **stockdb-ai 应用层服务**<br>托管 MCP 服务器、Web 运维 API 与静态面板 | **外部消费方首要入口**<br>`POST /mcp` 免 Token；`/api/*` 需 Token；`/` 供运维人看 |
| **`7899`** | **`7899`** | `/opt/stockdb/stockdb` (PID 12) | HTTP/1.1 (私有指令)<br>MsgPack 二进制 | **底层 LevelDB 存储引擎**<br>原始 A 股未复权日K段、股票代码表键值存取 | **容器内私有依赖**<br>仅供 `app.py` 与原生 SDK 内部调用，不对外提供通用 API |
| **无监听** | **`8080`** | `python /opt/webui/app.py` | 同 8081 | 容器内进程绑定的实际端口 | 容器内回环 `127.0.0.1:8080` |

### 核心事实断言：
1. **8081 不是前端页面代理，而是真实后端服务的宿主机映射端口**：
   - 容器内应用进程监听 `0.0.0.0:8080`，宿主机通过 Docker NAT 将外部 `8081` 映射至容器 `8080`。
   - `POST /mcp` 是该后端服务的核心原生路由，直接调用 Python 内存中的 `stockdb_mcp_server.dispatch`。
   - 它**完全独立于前端 HTML/CSS/JS**，即使把容器内前端静态资源目录彻底移除，`POST /mcp` 依然 100% 正常运行。
2. **7899 不是业务后端，而是底层存储引擎私有端口**：
   - 该进程由 upstream C++ 二进制直接驱动，仅识别 `/?cmd=get|vals&t=...` 指令，返回原始 MsgPack 字节流。
   - 对 7899 发起 `GET /`、`POST /mcp` 或 `GET /api/version` 均统一返回 `400 Bad Request: {"error":"invalid request"}`。
   - 7899 不具备行情合同校验、不具备指数/板块数据、不具备前/后复权算法、不具备快照管理能力，绝不能作为消费方接入入口。

## 3. 常见业务场景下的内部流转

1. **标准日频查询 (`get_kline`, fq=none)**：
   - 消费方请求 `100.66.1.5:8081/mcp` -> 进入 Python 进程 -> `market_v3` 校验入参 -> 经 `free_stockdb.fetch` 访问容器内 `127.0.0.1:7899/?cmd=vals&t=日k:<code>:...` -> LevelDB 返回 MsgPack 原始行情 -> Python 反序列化并组装为 v3 规范信封返回。
2. **复权日频重算 (`get_kline`, fq=qfq/hfq)**：
   - 经 8081/mcp 进入 -> 日K基础数据向 7899 取原始价 -> 复权因子向内存/SQLite 快照读取 -> 在 Python 内存中应用 `affine-v1` 仿射算法实时重算 -> 校验一致性并返回。
3. **指数序列查询 (`000001.SH`, `399001.SZ` 等)**：
   - 7899 引擎内无指数数据；`market_v3` 识别指数命名空间后，直接由应用层调度外部权威公开源（腾讯/新浪轮转）或本地 research 缓存，**完全不经过 7899**。
4. **昨日涨停今日开盘收益 (`get_board_open_effect_history`)**：
   - 全市场请求：直接由应用层读取挂载卷 `/mydb/` 中的 SQLite / DuckDB 预计算数据，130ms 极速返回，**不经过 7899**。
   - 调试子集请求：由应用层向 7899 取该几只股票的基础日K，在内存中动态判定涨停与开盘收益，隔离全市场盲目覆盖。
5. **原生 SDK 慢请求隔离 (`get_call_auction` 等)**：
   - 经 8081/mcp 进入 -> `sdk_bridge` fork 独立子进程 -> 子进程向容器内 `127.0.0.1:7899/?cmd=get&t=mapi_url` 读取上游网关 IP -> 尝试直连外部 IP `8.138.149.215:12328` -> 遇网络黑洞触发 10.0s 硬限被强杀回收，不阻塞主服务事件循环。

## 4. 消费方唯一推荐入口与架构结论

- **唯一推荐入口**：**`http://100.66.1.5:8081/mcp`**（局域网直连使用 `http://192.168.50.146:8081/mcp`）。
- **结论性判定**：
  1. 当前部署完全符合后端 API 架构标准，**属于合理的“应用服务与数据引擎同机解耦”模式**。
  2. 8081/mcp 本身就是稳定的后端 API，消费方接入它即为直接使用后端，不存在任何对前端页面的依赖。
  3. 本次收口属于**文档澄清与定义收敛**，无需且不应变更现有网络端口监听与映射，保持生产兼容性零风险。
