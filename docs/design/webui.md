# WebUI 信息架构设计（0.10.18 第四批定稿）

> 定位溯源：`docs/ROADMAP.md`「webui 运维面板为辅助驾驶舱（冻结）」。
> 本文件回答两个问题：**这个项目的 WebUI 是什么**（定义），以及**界面按什么规矩做**
> （判据）。此后任何面板改动（结构/文案/交互）对着 §3 判据验收；纯代码重构
> （等价迁移）仍走原面板冻结纪律，不受本文件约束。

## 1. 定义：WebUI 是什么

**stockdb-ai 的 WebUI 不是产品，是"个人 A 股数据基座"的远程运维台。**

- 核心产品 = AI 友好的数据接口（MCP 56 工具 + HTTP API + 列式仓库层）；
- WebUI 的唯一用户 = 站长本人，使用方式 = **低频、带目的的来访**；
- 唯一使命 = 让数据管道"持续新鲜、持续可用"，异常时提供就地处置。

**成功标准：开门 30 秒得到答案并离开。停留时间越短，设计越成功。**
它不是分析工作台，不与核心产品争夺注意力——这是"面板冻结"纪律的产品学依据。

### 1.1 三个真实场景

| 场景 | 频次 | 时长 | 页面要做的 |
|---|---|---|---|
| 每日巡检 | 每天 | <30s | 回答"昨晚同步成功没？数据到哪天了？"——要结论，不要点击 |
| 异常处置 | 偶发 | ~2min | 定位（同步挂了？磁盘满？进程停了？）→ 当场处置 → 走人 |
| 低频操作 | 偶发 | 不定 | 手动同步、改定时、查 mydb、翻告警/日志 |

## 2. 页面结构（DSM 存储管理器范式：健康灯 → 分区 → 异常指引）

参照系：群晖 DSM 原厂面板的"健康灯 → 分区 → 异常向导"；交互模式只用
NAS/运维面板的既有惯例，不发明新交互（§3 判据 6）。

### 2.1 总览页（驾驶舱 = NAS 信息中心）

```
┌─────────────────────────────────────────────────┐
│ 总览   ● 正常 · ●数据 08-29 · ●同步 空闲·成功     │  ← 聚合灯 + 域灯行（灯可点→跳运维页）
│                     ●服务 98.8% · ●系统 磁盘 44%  │     最近刷新 [刷新]
├────────────────────────┬────────────────────────┤
│ ▌数据资产               │ ▌同步                   │  ← 分区卡（各带灯/关键值）
│   最新 08-29 · 滞后 0   │   上次 08-29 15:00 成功  │
│   覆盖 1990~2026        │   下载 3120 文件 → 详情  │
│ ▌告警（2）              │ ▌版本                   │
│   • 最近 3 条极简       │   v0.10.17 · 已是最新   │
└────────────────────────┴────────────────────────┘
```

- 域灯四域：数据（新鲜度）/ 同步（管道结果）/ 服务（MCP 质量）/ 系统（进程+磁盘）；
- 灯色语义：绿=正常，黄=需要注意，红=故障，灰=未知；聚合灯 = 四域最差色。

### 2.2 数据同步页（运维页 = 存储管理器）

```
┌ 同步状态 ────────────────────────────────────────┐
│ ● 空闲 · 上次成功        [立即热更新] [停服严格]  │  ← 灯+状态词，操作同位
│   上次 08-29 15:00 · 下载 3120 文件               │
├ 前提检查 ──────────────────── ● 全部就绪 ────────┤  ← 全绿收成一行；有红自动展开
│（展开时逐项：进程/调度器/更新程序/数据源/数据卷/   │     异常项附处置链接：
│  待重试，红黄绿点 + 人话详情）                     │     完整诊断 · 日志中心
├ 数据资产 ────────────────────────────────────────┤
│   数据最新 · 股票 · ETF · 其他 · 覆盖 · 行情响应  │
├ 磁盘 ────────────────────────────────────────────┤
│   ▓▓▓▓░░░░ 44% · 477.6 GB 可用                   │
├ 定时自动同步 ────────────────────────────────────┤
├ 同步历史 / 同步日志 ─────────────────────────────┤
└ 同步耗时趋势 ▾（默认折叠，图表=钻取）────────────┘
```

## 3. 设计判据（验收清单）

1. **状态灯先行**：每页首屏是"灯 + 标准状态词"（正常/需要注意/故障/未知），
   不是裸指标平铺，也不是散文句；
2. **状态与操作同位**：看到状态的同时手就放在操作按钮上；
3. **正常安静、异常才展开**：检查类信息全绿收起，有红自动摊开，异常自带
   处置链接（单步指引即"向导"在辅助面板里的合理尺寸，不做多步 wizard）；
4. **说人话**：后端字段名（`code_stats.stock` 之类）不许出现在界面上；
   孤立指标要合成可行动的结论（"今天定时不会跑"）；
5. **图表是钻取**：趋势/分布图折叠或进详情页，不占运维页首屏；
6. **惯例优先**：只用 NAS/运维面板的既有交互模式，不发明新组件形态。

判据的来源（讨论存档）：定义先行 → 判据推导 → 才是参照物筛选。
Uptime Kuma（巡检结论先行）、Dockge（状态-操作同位）、beszel（图表钻取、
轻量）、Cockpit（渐进披露）为正参照；1Panel（通用建站面板，方向不符）、
Grafana（分析工具，场景相反）经定义筛选后排除，仅取文案/反面参照。

## 4. 与代码结构的接口

- 视觉语言不动：仍用 base.css 主题变量 + card.css 骨架 + StatCard/StatGrid，
  本设计只重排信息架构与文案，不引入新 UI 库；
- 状态机继续留在 composables/（use-sync/use-schedule/use-hk/use-overview…），
  总览页新增的 /api/status 拉取归 use-overview.js，视图仍零取数；
- 灯（状态点）是纯样式：`.light-dot` + tone 类，样式层实现，不做组件；
- 验收仍为：vitest 全绿 + vite build 通过 + views 层零直连（fetch/setInterval）。
