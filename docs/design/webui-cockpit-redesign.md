# W1 · webui 单页驾驶舱重设计定义书（v0）

> 性质：工程重设计（非研究课题），沿用 research/TEMPLATE 十节纪律做适配版。
> 口径（§2）一经实现即冻结；要改必须升版本（v0→v1）并在文末留痕。
> 状态：draft（2026-09-06 起草，方向 A 已由用户拍板认可）
> 出处：用户 2026-09-06「交互方式和展示内容可以再重新设计」（方向 A 认可）
> 关联：ROADMAP §2「webui 冻结不加功能」——本设计为**纯重组展示、零新功能**，
> 不触发冻结条款；实施前在 ROADMAP 附一行指针即可。

## 1. 问题定义（一句话）

webui 按后端模块分 8 页、重复回答「系统好吗」三遍（总览/系统健康/诊断中心）
且展示服务器内部细节而非用户答案——重设计为**单页驾驶舱 + 4 抽屉**，
使「确认健康 + 看近期事件 + 触发同步」的值守动作在单页 ≤2 次点击完成。

## 2. 信息架构口径（工程版「因子口径」）

### 2.1 页面收敛：8 → 1

| 旧页面 | 去向 |
|---|---|
| 总览 | 驾驶舱主体（状态带 + 时间线 + 异常区） |
| 系统健康 + 诊断中心 | 合并 → 「诊断」抽屉 |
| 通知中心 | 「告警」抽屉（明细全量；同类聚合计数） |
| 日志中心 | 「日志」抽屉（sync + 容器聚合，现行为不变） |
| 私有存储 | 「数据查询」抽屉（读侧全保留；写侧收进抽屉二级标签） |
| MCP 观测 | 「诊断」抽屉的 MCP 标签页（调用统计属诊断信息） |

旧路由 /ops/* 全部 200 重定向到驾驶舱并自动展开对应抽屉（书签兼容）。

### 2.2 常驻状态带（四灯，判定口径写死）

| 灯 | 数据源 | 绿 | 黄 | 红 |
|---|---|---|---|---|
| 数据 | /api/health | lag=0 | lag 1~2 | lag≥3 或探针失败 |
| 同步 | /api/schedule | enabled 且最近触发 exit=0 且无 retry_pending | retry_pending 挂起 | 最近触发 exit≠0 |
| 仓库 | /api/warehouse/status | watermark==data_latest 且最近对账 ok | watermark 落后 1 日 | 对账差异/schema 落后告警 |
| 磁盘 | /api/diag | used<80% | <90% | ≥90% |

灯语义 = 「点它开对应抽屉」：任意非绿即可点击展开定位，异常区只在有黄/红时出现。

### 2.3 时间线（驾驶舱主体）

最近 7 个交易日，每日一行：沉淀（rows/对账 ok 差异）/ 同步（trigger+verified+
时长）/ 备份（warehouse 备份文件落盘）/ 告警计数。行内异常标红。正常日 =
安静的一行灰字，值守 = 扫 7 行。

### 2.4 顶栏常驻

「立即热更新」按钮（二次确认：显示当前 watermark 与最新交易日）、主题切换、
告警计数徽标。全部干预动作 ≤1 次点击可达；危险动作（重启 stockdb）仅存在于
诊断抽屉内且双重确认。

### 2.5 展示内容取舍

删：镜像 tag、状态原文、进程内部字段（除非异常时在抽屉中展示）、重复的告警卡。
增：备份年龄（距上次 warehouse 备份的小时数）、调度倒计时（下次同步）、
对账差异计数。原则 = 展示「答案与偏差」，不展示「实现细节」。

## 3. 假设（可被打脸）

- H1: 90% 的面板访问是「确认健康 + 偶尔触发同步」→ 单页覆盖后跳页次数归零。
- H2: 排障入口改为时间线先行（定位日期）→ 抽屉深挖，日志页作为首站的次数
  趋近于零。
- H3: 私有存储的写侧低频到可以收进二级标签而不损失可用性。

## 4. 数据与窗口（现有资产盘点）

- 已有端点可直接用：/api/overview（health+alerts+version 聚合）、/api/health、
  /api/schedule、/api/diag、/api/log、/api/alerts*、/api/data/tables+read、
  /api/warehouse/status、/api/mcp/*、/api/history（sync_history 全条目：
  ts/trigger/exit_code/verified/duration/data_latest/warn）
- **唯一缺口**：沉淀/对账/备份的逐日历史只存在于 records jsonl 与日志文件，
  无 API。解决 = 新增**一个只读聚合端点** `/api/timeline`（后端聚合 records +
  备份目录 + history，按交易日分组返回 ≤14 天）——这是本设计唯一的后端增量，
  除此之外零后端改动。
- 前端组件资产（第六批皮肤全部复用）：card/StatGrid/el-drawer/el-timeline/
  状态点样式；浅/深双主题变量体系直接生效。

## 5. 交互规则草案 v0

- 四灯任意非绿 → 时间线上方出现异常区（自动列出非绿项 + 「展开定位」按钮）。
- 热更新：点击 → 确认弹层（watermark/最新交易日/上次同步结果三行）→ 触发 →
  按钮进入进行中态（轮询 /api/log 尾部 10 行滚动展示）。
- 时间线行点击 → 展开该日明细（告警 + 同步 + 沉淀原始条目）。
- 全部轮询节奏沿用 usePolling 现状（15s 自动刷新），不新增轮询端点。

## 6. 验证设计

- 对照基准：旧 8 页布局。
- 指标：①值守动作（确认四灯+看时间线+触发同步）点击次数（目标 ≤2，基线 8 页
  布局 ≥6 次跳转）；②首屏信息完整度（四灯+时间线一屏内，无滚动）；③Vitest
  空载荷挂载防线按新结构重写后全绿；④浅/深双主题目测（延续第六批标准）。

## 7. 验收标准（缺一不算完成）

1. 单页 ≤2 次点击完成值守三动作，页面跳转 0 次。
2. 8 个旧路由全部 200 且重定向展开对应抽屉。
3. `/api/timeline` 单端点交付（无其他后端改动），时间线 7 个交易日数据完整。
4. Vitest 全绿（含重写后的挂载防线），浅/深双主题目测通过。
5. 皮肤第六批视觉体系零回退。

## 8. 判废标准

- 盘点后发现时间线需要 >1 个新端点或 records 数据不足以按日聚合 → 判废，
  降级方向 B（轻量修剪：合并健康+诊断、告警降噪）重议。
- 首屏信息密度目测过载（>2 屏滚动）→ 单页假设破产，回到分页模型。

## 9. 复现协议

- 设计定稿截图存 docs/design/assets/webui-cockpit/（浅/深双主题 + 抽屉展开态）。
- 实现按批走 PR：每批 CHANGELOG + 新旧对比截图 + Vitest 全绿，正文引用本文档
  章节号；口径变更走 v0→v1 留痕。

## 10. 明确不做

- 不做 AI 对话框（方案 C：需修订 ROADMAP 冻结条款，另立项另议）。
- 不加执行/交易/下单类按钮（ROADMAP §4 戒律）。
- 不新增除 /api/timeline 外的任何后端端点；不改 MCP。
- 不动 /legacy 旧面板。
- 不做移动端专门布局（窄屏降级即可：四灯保留、时间线缩至 3 天）。
