# 联合验收规格

## 1. 四种证据层级

| 阶段 | 执行人 | 能证明什么 |
|---|---|---|
| offline | 双方 | schema、合成样例、部分不变量及负例；不能证明市场事实 |
| service | NAS维护Agent | 源码实现、单元/注入测试、真实数据及实际部署端点 |
| client | 本项目Agent | 客户端按同一合同解析、保留血缘、正确处理失败 |
| joint | 本项目Agent，必要时NAS配合 | 实际NAS→隔离发布→data_core默认读回→逐数据集切换 |

每条case以及case内每条断言分别报告PASS/FAIL/BLOCKED/NOT_RUN。
PASS必须有证据文件路径及hash、实际命令或请求、时间、版本/build、比较结果；空证据不得PASS。
BLOCKED说明外部条件/源限制；NOT_RUN说明未执行原因。两者均不等于PASS。
J类由本项目运行，服务回传标NOT_RUN是正常边界。服务其他必验项不能因此被省略。
本包不设多日观察前置条件，不制造历史运行；真实单次验收和质量审计仍是硬条件。

## 2. 逐项矩阵

机器权威清单为`acceptance-cases.json`，共S/I/H/A/J五组；每组每项均有逐断言要求。

| 分组 | 范围 | 责任 |
|---|---|---|
| S01—S08 | 合同完整性、工具schema、既有核心回归、能力发现、兼容、资源、错误、隐私 | service，双方消费相关断言共享 |
| I01—I10 | 指数身份、板块序列、单位、元数据、独立比对、缓存隔离与拒绝 | service+client |
| H01—H10 | 250/500日窗口、长日历、分页、gap、limit、同快照分段、上限、时间、1000日探测 | service+client |
| A01—A20 | 因子schema、公式、锚点、真实事件、负价格、量额、R/F/A关联、修订、重启、精度、错误 | service+client |
| J01—J08 | 项目能力匹配、指数板块发布、因子消费、用途门槛、备用、核心保护、审计、逐项放行 | project |

H10为可选1000日能力探测，未支持可NOT_RUN/明确拒绝，但必须声明原因，不能静默截断。
7个同花顺参考序列为可选支持矩阵项；命名空间隔离/不冒充BK的负例仍为必验。
四指数、七东财板块、qfq和hfq均是本次目标；部分完成必须逐项列出，不能缩小目标后给整批PASS。

## 3. 真实测试样本与窗口

### 3.1 动态截止与公开样本

选T为最近有可核验final依据的已完成交易日，记录绝对日期和确定方法。
由已验证交易日历计算最近250/500个槽位；测试请求显式start/end，不写死过去行情作为当前真值。
样本表只含公开证券键、选择规则、上市/编制日期公开引用，不附本地持仓关系。

- A：DEVELOPMENT列出的4指数、7东财BK；每证券完整六字段或量额缺失的清晰分层结果。
- B：至少4只成熟股票（沪深各2）和2只成熟ETF（沪深各1），500日跨度；
  至少两个真实除权事件（纯现金、送股/转增/拆合之一），合成测试补齐现金+送转组合与合法负值。
- ETF必须实际验证基金份额/价格调整事件或有公开证据的无事件窗口，不能用股票因子复制冒充ETF支持。
- 另选有公开证据的停牌/上市前样本验证合法gap，并注入未知空、源错误和历史不足。

### 3.2 对照与容差

身份、日期、范围、周期、复权、锚点、因子引用、单位、状态：完全一致，无容差。
同一捕获快照的单票/批量/分段/字段投影：规范化行值与来源元数据一致，hash按各投影重新计算。

外部比价先证明同一原始序列、提供者/编制版本、日期、单位和修订口径：

1. OHLC双方用ROUND_HALF_UP舍入到较低已声明小数精度p，绝对差不得超过`10^-p`；
   不得根据已看到的误差扩大阈值。每个点的原值、精度、差值、判定均留表。
2. 相同单位定义的整数volume须精确相等。amount按较低声明精度舍入后至多差一个最末位单位。
3. 单位/成分统计口径不一致时不进入数值通过率，列为不可比及受影响用途，不能算PASS。
4. price-only与full-OHLCV分别报告；当前项目量能相关指标只接收后者或另行验收的明确用途。

每个必验指数/板块至少对照末5日和窗口内固定规则抽取的5日；B股票/ETF至少末5日及每个除权事件前后各3日。
另对成熟样本执行全窗口结构、覆盖、非空、排序和内部一致性检查。
外部对照不得只是NAS同一缓存的两种包装；保留原始公开参考和实际访问方式。

### 3.3 因子回算的两道验收

- 内部一致性：R、F、A逐证券逐日逐OHLC回算，Decimal与声明精度ROUND_HALF_UP结果精确相等；量额不变。
- 经济语义：真实公司行动/原始因子来源与实现公式的对应，及独立公开调整序列或独立实现对照。
  对照锚点不同必须先按可证明的规则统一，不能只比较收益曲线“看起来接近”。

仅有“NAS自己返回的因子能算出NAS自己返回的复权价”不足以完成B；真实公式/源字段无法确认则B为BLOCKED。
负数或零复权价使用明确合成用例验证，样例不是对真实证券出现负价的声明。

## 4. 必验故障与恢复

1. 单证券源超时、全部源失败、源结构变形、未知证券、错误namespace、错误周期/复权、未完成锚点。
2. 错因子快照、错fq、错锚点、范围扩张、把行情与因子快照互传、快照缺失/到期。
3. 上游修订后重读旧R/F/A，旧值不变；创建新快照，新值和hash变化可解释。
4. 服务/容器正常重启，未到期扩展R/F/A仍可读；到期错误可重复复现。
5. 冷缓存500日请求、声明并发下500日批量；请求总期限不超过声明且<=30秒。
6. 至少20次慢负载期间状态调用，NAS本地p95<=2秒；超时/满载后普通日K及核心握手恢复。
7. 超行数上限、max_codes边界、limit正数：明确partial/错误，不丢尾页后假完整。
8. 错误信封被实际tools/list的outputSchema接受，structuredContent与JSON文本一致。

报告实际资源配置、冷热缓存、证券/行数、耗时、队列/执行情况和恢复证据；不能只报平均延迟。
无真实注入权限时提交可执行注入测试及BLOCKED原因，不以mock结果替代部署恢复结果。

## 5. 消费方联合验收

服务Agent交付后，本项目将：

- 按profile核验扩展能力，增加因子解析与锚点参数，保留3.0.0核心路径。
- 隔离根目录跑指数/板块及R/F/A；检验本地identity、series、方法和复权维度不会覆盖现有序列。
- 将null量额、合法复权非正价格、合法gap分别按用途处理，避免套用当前股票主链路的正价格和连续60行规则。
- 以same-source/series/version/adjustment读取，不把BK/THS、原始/复权或修订窗口逐日拼接。
- 验证故障整段回退及原因留痕，确保新profile问题不阻塞现有股票/ETF主源。
- 经既有数据产品服务发布并从data_core默认读回，完成边界/数仓审计后逐数据集启用。

相关项目文件：`scripts/stockdb_http_client.py`、`scripts/stockdb_market_contract.py`、
`scripts/stockdb_daily_collection.py`、`scripts/update_market_data.py`、`mingli_app/kline_sources.py`、
`mingli_app/kline_readiness.py`、`mingli_app/market_data_contracts.py`、`mingli_app/data_products/`、
`data_core/serving/analytical.py`及对应测试。改动须保持本项目架构边界。

共同检查包括：StockDB相关测试、`audit_sqlite_boundaries.py`、`audit_data_source_boundaries.py`、
`update_data_products.py audit`；如影响业务收盘/估值，再执行一致性与SQLite strict审计。
不要求NAS维护Agent在其他工作区运行这些项目命令；其本机结果不能代表消费方已通过。

## 6. 完成判定与回传目录

A完成：四指数和七BK各自必验项全部服务PASS；price-only/量能受限明确区分，不虚报全部复盘用途。
B完成：成熟股票/ETF500日、qfq/hfq、真实事件、R/F/A回算/重放/重启、错误与兼容必验项全部服务PASS。
任一必验序列/模式BLOCKED，则对应批次只能部分完成，其他已通过序列仍可交付。
项目完成：对应J类client/joint断言通过，并有实际发布及默认读回；服务维护Agent不代写该结论。

```text
stockdb-research-extension-return/
  delivery-summary.md
  support-matrix.json
  acceptance-report.json
  contract/                 # 原样补充合同、基线与schema
  source/                   # diff、commit与构建/回退说明
  deployment/               # initialize、tools-list、status、脱敏配置
  live/                     # 请求/响应、范围、外部参考、逐点比较、R/F/A
  injected/                 # 合成/故障注入测试与输出
  logs/                     # 日志与复现命令
  MANIFEST.sha256.json
```

所有JSON必须是单个合法JSON值；不追加日志。所有路径为包内相对路径；报告引用附SHA256。
不回传令牌、密码、宿主秘密路径、业务数据库、持仓/交易文件或与验收无关的大块原始数据。
必要的公开原始对照与R/F/A样本可以包含；大窗口可交压缩公开证据及覆盖/hash表，但须可独立复现全窗口比较。
